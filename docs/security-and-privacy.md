# 安全与隐私基线

本报告区分 M0 原版调查与当前定制实现。文件处理无外发的结论仍必须以对应工具的实际请求记录为界，不能泛化至未验收的全部工具。

## 当前定制实现

- 图标使用固定来源的本地几何数据和 Iconify 离线组件，不具备运行时公共 API 加载能力；原站 GitHub iframe/推广已移除。
- Monaco 编辑器和各语言 Worker 随站点打包。FFmpeg 核心改为 npm 锁定版本 0.12.10 的同源 JS/WASM，没有 CDN 兜底；没有将原站所有媒体能力因 GPL 一并关闭。
- 只发布白名单 public 资源，不分发模拟 Ghostscript、未核实的旧字体/旧品牌资产。系统字体不隐式向外站取字体。
- CSP 限制连接、图片、字体、脚本与 Worker 的来源；保留本地/blob PDF 结果预览，不放行第三方 frame。现有计算工具所需动态求值仍允许，不能宣传为最严格脚本策略。
- Markdown 预览在产生 HTML 时移除图片/HTML/可跳转链接，导出也忽略图片与 HTML，覆盖库的默认取图适配器。界面说明这一限制，不静默承诺图文完整转换。
- 图片压缩限制文件、像素、总字节、并发与总时间。新输入/设置废弃旧下载，取消/重置/离页释放结果；支持的 JPEG EXIF 仍保留，明确可能含拍摄位置，不作为脱敏能力。

最终浏览器样本、网络请求范围和未验收项见 `acceptance-report.md`，以实际结果为准。

## M0 原版实测与源码发现（历史基线）

- 原版首页桌面/手机可打开，无 pageerror；截图和请求记录在 `evidence/upstream-*`。
- 首页记录有 ghbtns/GitHub 及 Iconify/备用图标 API 等外站请求。日志只记方法、去掉查询参数的目的地及是否有 body，不保存正文或文件名。首页无正文请求不证明文件处理过程无上传。
- Navbar 内有 GitHub iframe 和推广/社区入口。定制版应移除自动加载第三方 iframe，保留正常可点击的开源归属链接。
- FFmpeg、Ghostscript、Tesseract、背景模型及通用图片压缩 Worker 有外部资源或默认地址，需要逐项本地化；不能把文件在浏览器处理与无外部请求混为一谈。
- 现有收藏只保存工具路径。不要保存上传文件、Markdown 正文、文件名或转换结果。
- 通用图片压缩原版批量 Promise.all 无并发上限，固定尺寸策略及异常降级需在原入口内修复。PDF Worker 缺超时/错误/取消边界，不能当成稳定公共能力开放。

## 首版必须满足的处理边界

新工具只在浏览器处理，重型操作按需加载。每个工具明确格式、大小/像素、队列与时间上限；取消/重置/离页清理 object URL、ImageBitmap、Worker 和临时结果。逐文件失败不能只 console.error 或伪装全批成功。

Markdown 的外链图片必须经专门适配策略，不能依赖库默认自动下载。新引擎资源和模型必须本站托管并核来源许可；不以第三方 URL 作为失败兜底。图标也需自托管或构建时内联，首页不能依赖未知外站。

工具站的 CSP、COOP/COEP、缓存和可能的 Service Worker 只作用于独立应用，禁止改主站或 Chat/OIDC 的全局策略。首版不启后端转换、匿名上传、分析埋点或文件云存储。

## 待做验收

用真实但非敏感样本，对每个开放工具记录处理期间请求方法/目的地，确认没有文件内容外发；覆盖失败、取消、重复文件名、损坏文件、大文件与手机状态。本轮已测范围记录在验收报告中；不得将这些样本的无外发结果推广为未开放能力或全部恶意输入已经通过安全审计。
