# 功能缺口与采用决策

依据：M0 锁定上游 132 项源码清单、7 个候选仓库固定提交、README/依赖清单，以及 DoxDock/PDFSlice 的抽样实现。审计快照在 `evidence/sources/`；未把候选 README 的功能宣传作为测试通过证据。当前已在独立项目实现 Markdown→Word 和通用图片压缩增强，最终结果见验收报告；本表保留来源选择与后续 PDF/语音的范围边界。

## 已有能力优先

上游已有通用图片压缩 `/image-generic/compress`、PNG 压缩 `/png/compress-png`、裁剪、尺寸调整、格式转换、图片编辑，以及 PDF 合并、拆分、旋转、转 PNG、图片转 PDF、提取图片、表单和编辑器。现有 PDF 编辑器内部能力尚未实测，不能仅因没有独立路由就重复新增同类工具。

| 来源 | 比对结论 | 采用策略 | 成本判断及待验证项 |
|---|---|---|---|
| markdown-docx | 上游无 Markdown→DOCX 注册入口，属于明确缺失 | 已精确集成 `markdown-docx@1.7.1`，复用 npm 包而非演示站 | 注册、双语、文件/粘贴、取消/超时及真实 DOCX 已实现；Word 样本可见中文、表格、代码和公式。库默认取图已由 ignoreImage 与禁止取图的 imageAdapter 覆盖，界面明示不导入图片/HTML |
| Squoosh | 图片压缩已存在，属于增强 | 不移植整站、不使用旧 CLI/lib；优先现有浏览器编码能力，再逐一评估 codec | 中至高：PNG 质量参数与 JPEG 不等义；AVIF 需浏览器和资源体积验证。README 有 Analytics 说明，不能照搬站点代码；本次旧 CLI/lib README 路径返回 404，不猜现行包维护状态 |
| DoxDock | 合并/拆分/旋转/图片转换重复；页面排序/删除、PDF 文本提取有潜在缺口 | 先确认 OmniTools 编辑器是否已覆盖；确有缺口再取最小 helper 思路 | 中：`organize-pdf/helpers.js` 使用 pdf-lib copyPages 重建顺序；需缩略图、取消、损坏/加密限制和实际页序测试。`extract-text/helpers.js` 明确扫描件不支持 OCR。尚未移植或跑其测试 |
| PDFSlice | README 声明很多已有功能；高级压缩、保护、涂黑不可直接承诺 | 暂不移植受复杂引擎约束的能力；水印/页码/元数据仅列候选，先核已有编辑器 | 高：检查的 `src/lib/pdfTools.ts` 包含 Worker 转换、`ignoreEncryption`、引擎 API 的 `any` 断言；不能以绕过加载检查冒充解密。涂黑走 Worker，未验证原文本是否不可恢复，不能贴安全脱敏标签 |
| Whisper Web | 没有语音识别工具，为缺失但不在首轮 | M4 默认不启动，不复制源码或模型 | 高：默认分支是 `distil-whisper-web`；仓库树无 LICENSE，不能假定 MIT。模型许可、中文精度、内存、取消、断网均待专项核查 |
| ConvertX | 属服务端复杂转换，不是浏览器缺口的直接补丁 | 不接入、不启匿名服务，M5 默认不启动 | 高且跨系统：AGPL、服务隔离、鉴权、限流、队列、保留/清理策略和独立发布许可；官方明确警告匿名/自由注册不可公开暴露 |
| Stirling-PDF | 大部分基础能力重复；高级引擎另有许可 | 不复制、不部署；不能以根 MIT 覆盖 engine | 高：根 LICENSE 明确目录例外，`engine/LICENSE` 限制生产使用；未有适合本次用途的授权证据 |

以上成本为对接复杂度判断，不是工期承诺；尚无移植实现和实际耗时，不能报告已测得的移植成本。

## 两个高频增强的具体合同

### Markdown→Word

- 新增一个工具，沿用 `defineTool`，建议路径 `/converters/markdown-to-docx`。
- `.md` 文件和粘贴内容在浏览器处理，不缓存正文；英文和中文翻译同步。
- 支持标题、列表、代码、引用、链接、表格与数学公式，以生成文件实际结构为准。未验证前不承诺 Office 排版一致。
- 图片不允许默认外链自动下载；先提供明确限制和可读错误，再考虑显式授权的资源加载。
- 空输入、损坏/超限输入、转换异常、下载失败均必须反馈；DOCX 需解包检查正文/结构并实际渲染抽查。

### 通用图片压缩增强

- 保留 `/image-generic/compress`，不另建第二个同名入口。PNG 专用工具也保留，说明与通用工具的边界。
- 原版服务使用无限制 `Promise.all`、固定最长边 1920、Worker 默认库地址和保留 EXIF；失败时可能只返回部分结果。保留 EXIF 是原有测试明确检查的行为，不能未经设计就删除测试或改成相反预期。
- 增加格式/尺寸选择、质量滑块、逐文件状态、原始/结果 KB、预览比较、取消及 ZIP。限制像素、总大小、队列长度和并发；结束释放资源。
- 同名文件不能在 ZIP 内相互覆盖；本地 JPEG/PNG/WebP 优先，AVIF 不默认开放。
- Worker/编码器不从 CDN 默认取资源。输出不是越小越好，格式变化和透明度变化要明示；同格式变大时报告无收益，不冒称压缩成功。

## 进入下一阶段前

用户已接受适用许可证的源码义务，非 MIT 不构成功能禁用依据；媒体与 HEIC 能力已恢复，本地资源适配按实际构建检查。无明确来源的二进制或尚未准备好的模型暂不进入产物，旧路径显示资源原因，不拿公共共享服务作兜底。全面原生工具验收与生产对应源码材料仍须完成，不以本轮两个重点工具的成功代替。
